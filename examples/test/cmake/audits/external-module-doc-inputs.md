# XML prerequisite audit: external user-module documentation inputs

Copyright (C) 2026 Qore Technologies, s.r.o.

Scope: CMake helper, Python regression, module-structure guidance and release notes.
The full audit-changes skill and its referenced module structure, sandboxing,
cancellation and DataProvider guides were reviewed. All 62 checklist items follow.
No native, astparser, runtime or Qore-language source is changed by this core commit.

Root cause: QORE_EXTERNAL_USER_MODULE used its installation file list to build
Doxygen INPUT without selecting Qdx source files. SVG/YAML/JSON/protocol resources
therefore became nonexistent .dox.h paths. Selection now matches .qm/.qc processing,
while the installation list is preserved.

Validation: python3 -m unittest discover -s examples/test/cmake -v passes all five
cases on CMake 4.3.0 and with CMAKE_EXECUTABLE selecting CMake 3.18.4. Existing
checks cover resource bytes/install paths, documentation-off configuration,
dependency ordering/reconfiguration and rejected missing dependencies. The new
case covers single-file and directory documentation with misleading resource
suffixes. Its directory subtest fails against the pre-fix helper as expected.
Logs: /tmp/wsdl-p3-11-core-cmake{,318,-baseline}.log.

Integration: module-xml build-debug configured with an uninstalled copy of the
updated helper, retaining Debug and /usr. Qdx/Doxygen generated SoapDataProvider
documentation without missing-input warnings; separate XML edits correct stale
API references. Logs: /tmp/wsdl-p3-11-final-{configure,provider-docs}.log.
No installed Qore files were changed and no core runtime rebuild was needed.
Valgrind is not applicable because this core change contains no C++.
