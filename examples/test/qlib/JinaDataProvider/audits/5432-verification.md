## Batch worker root cause

These requests used only the required fields, with one short record:

```json
{
  "model": "jina-embeddings-v5-text-nano",
  "input": [
    {"custom_id": "qore-5432-followup", "body": {"input": "Delivery status"}}
  ]
}
```

The second request changed only the model to `jina-embeddings-v5-text-small`.
Neither request sent `batch_size`, dimensions, normalization, task, or a webhook.

|!Model|!Batch ID|!Submission|!Terminal result
|jina-embeddings-v5-text-nano|batch_211e896097a8|200, pending|failed
|jina-embeddings-v5-text-small|batch_f7d7ccbf94ae|200, pending|failed

Both returned this exact terminal error:

```text
process_batch_inputs() got an unexpected keyword argument 'batch_size'
```

The failure is an **incompatible internal function call in Jina's worker**: its caller supplies a
keyword that the deployed `process_batch_inputs` function does not accept. It is independent of
Qore serialization and occurs with both supported models using required fields only. A mismatch
between deployed worker versions is a plausible explanation, but cannot be proven without vendor
source or logs. Repair requires aligning the worker caller and callee at Jina; dropping a Qore
request field cannot fix it because no such field was sent.

Both diagnostic jobs are terminal failures. No polling loop was used and no active diagnostic job
was left running. These failed jobs have no completed embedding output to download.

## Experimental EU endpoints

Jina's Reader documentation advertises experimental EU residency. Both `eu.r.jina.ai` and
`eu.s.jina.ai` returned DNS NXDOMAIN, also confirmed through Google's public DNS-over-HTTPS resolver.
This is missing public DNS, not a local resolver-only failure. Global endpoints work. The provider
preserves the requested region and propagates the error; silently routing an EU request elsewhere
would violate the user's region selection.
