## Implemented behavior

The Azure OpenAI connection authenticates synchronous, asynchronous, raw, copied, and ping requests.
The application exposes 99 explicit operations and the generic API-call action. The original chat and
embedding identities and deployment inputs remain stable; legacy public classes retain their dated routes.
Requests use a pinned, pruned Microsoft v1 description with checked import repairs, typed nested options,
finite choices, resource references, and date outputs. The 12 standard locale catalogs cover the complete
recursive presentation graph.

Shared fixes preserve empty JSON schemas and values, discriminator-derived fields, multipart structured
fields and file arrays, uniform union codecs, namespace-qualified serialized container types, and empty
indexed-list element types. File-or-URL unions retain their existing presentation identities and composition
semantics, verified against Together AI.

## Follow-up corrections

Applied on 2026-09-12 after a review of the committed change, with the same checklist re-applied to
the corrected tree: 0 Fail. No C++ changed, so no Valgrind run was required; the Qore modules,
their qmods and the catalogs were rebuilt and re-verified.

- `OpenApi3DiscriminatorDataType` now overrides `getSoftType()`, `getOrNothingType()` and
  `getMandatoryType()`, and accepts nothing in its "or nothing" form. The inherited
  `QoreUnionDataType` versions returned a plain union, so an optional or nullable discriminated
  property was validated against whichever alternative matched rather than against the branch its
  discriminator names. Three Azure option types were affected, among them
  `create-container.network_policy`; every Azure branch pins its discriminator with an enum, so the
  observable loss there was branch selection and error quality rather than accepted invalid bodies.
- `RestSchemaConvertedUnionDataType` overrides the same three methods, so an optional converted
  union retains its conversion tree and its schema-backed wire contract.
- A discriminator mapping leading back to the schema that declares it, directly or through other
  mappings, now raises `INVALID-REFERENCE`. Validation follows mapping edges with the value
  unchanged, so a cyclic mapping previously exhausted the stack and terminated the process with
  SIGSEGV; `getDataType()` was already guarded by the composition stack, `check()` was not.
- `SchemaObject::getDiscriminatorReference()` is now the single definition of what a bare mapping
  value names, used by the schema parser and by `RestSchemaPruner`, which had its own copy.
- Both Azure modules return to `version = "1.0"` with their notes folded into the existing v1.0
  subsections: neither 1.0 has been released, so a 1.1 stamp would name no distributed artifact.
- The serialized-container release note moved out of the `@section qore_3_0_0` heading into
  `@par Qualified Container Types in Serialized Data`, beside the related serialization paragraph.
- The root catalog and all twelve locales carry 1,491 renamed message IDs. Only the type identity of
  a discriminated union changed: every `source` and `message` pair is unchanged, and the rename is a
  verified bijection produced from `bin/qore-data-provider-i18n` output.

New regressions: optional/soft/mandatory discriminator forms and mapping cycles
(`OpenApi3Discriminator.qtest`), the optional converted union (`RestSchemaUnionCodecs.qtest`), and
unqualified container types written by earlier versions (`NamespacedContainerTypes.qtest`).

Validation: 49 affected suites run with debugging enabled (1,265 cases, 38,051 assertions), 0 failures:
OpenApi3, RestSchemaActions, Serializable, Mime, both Azure suites and every other consumer of the
changed modules. `qore-data-provider-i18n --check --require-standard-locales
--require-complete-locales` verifies the Azure catalogs, and `--check-source-tree` verifies 135 owner
modules, 147 catalog domains and 1,591,054 translations.
